## Executed contention matrix and runtime

`yarn test:p2:container` builds `Containerfile.p2-test` with Node 24 and runs the harness from the host. The harness runs three actual shared-namespace pairs (HOST/HOST, HOST/CONTAINER, CONTAINER/CONTAINER), checks independent host control progress, exercises container crash/recreate, and asserts absent/malformed namespace failures. Participants share the host coordination directory mounted read/write. It is not a test of separate namespace copies.

The container harness uses Podman's `--security-opt label=disable` **only in this isolated test invocation** so its read-only source-checkout bind mount is usable without privately relabeling the checkout. This test-only setting is not a production recommendation, does not demonstrate a production SELinux configuration, and must not be used to work around shared-namespace labeling or permissions. Production requires an administrator-defined SELinux policy that grants the host service and container domain access to the same shared namespace label; see [Configuration](configuration.md#provisioning-a-shared-host-coordination-namespace).

The harness's parent effect receiver generates a per-run random token and passes it only through participant environments; HTTP requests authenticate with `x-p2-receiver-token` and the token is never written to logs or event evidence. The default bind address is `0.0.0.0` because rootless Podman's `host.containers.internal` gateway needs host-side ingress (host networking is not used). This is constrained to the dynamically assigned receiver port and protected by the unguessable per-run token; set `P2_RECEIVER_BIND` to a narrower host interface address where the Podman gateway permits it. Requests have a 64 KiB body cap and a 5 second deadline. Participants bound fetches and parent heartbeat waits, and receiver shutdown force-closes remaining sockets after its deadline.

Executed current harness 2026-11-07 using `yarn test:p2:container`: the image build succeeded and all three pairs (HOST/HOST, HOST/CONTAINER, CONTAINER/CONTAINER) rejected challengers with zero attempts/callbacks and no parent-received task actions. The parent effect receiver validated each task-facing event's persisted attempt ID, owner instance/token/generation, lease identity and integration identity against the durable `RunStore` record. It received one owner create, claim, and implementation-dispatch per pair, and the independent control emitted three heartbeats; the parent confirmed all three carried the same attempt and owner authority. After release, a normalized identity alias paired with a disjoint alternate runtime root was blocked against each still-active pin without task actions; restoring the original configuration resumed through the parent-observed authority. The harness inspected lock files from the common parent-visible mount and reported device/inode/owner metadata; it did not collect independent inode reports from both participants. All pair attempts reported generation 2.

All four negative variants (missing root/marker, wrong namespace, malformed owner) rejected before attempts/callbacks/task-facing events; malformed owner bytes were preserved. Crash/recreate retained the same attempt ID, advanced owner generation 1 -> 2, and preserved the serialized primary-session/worktree/branch resource-reference fields. These are durable references only: no actual OpenCode session was launched and no actual Git worktree or branch operation was executed by the fixture. Parent-observed create/claim/dispatch/resume counts were exactly once. Bounded waits, cleanup, and final Podman inventory completed; the harness emitted `"result":"PASS"` and found no harness-owned containers remaining. Namespace IDs, inodes, PIDs and temp paths are run-specific.

Runtime recorded for this run: Linux x86_64, Node `v24.18.0`, rootless Podman `5.8.9`, `crun 1.28`, image `node:24-bookworm-slim`. The harness emits structured JSON evidence on successful completion. No fixed run-specific inode or timestamp is asserted.

## Required operations and safe rollout

Provision `workflow.coordinationRoot` and `workflow.coordinationNamespaceId` explicitly; the example configuration includes both required placeholder fields. Follow [`configuration.md`](configuration.md#provisioning-a-shared-host-coordination-namespace): an administrator provisions the `/var/lib` parent and grants the dedicated service account ownership; run the fail-fast namespace command as that account from the application checkout with `tsx` installed. Use a private directory and a compatible Podman `--userns=keep-id` mapping, and mount the _same directory_ in all participants. Do not use `:Z`/`:z` for a shared namespace, privately relabel the shared namespace or source checkout, or disable SELinux labeling as an access workaround. The host administrator must configure SELinux policy for the service identity and container domain to access the same existing shared label. No credentials belong in this configuration.

Stop every old writer before enabling canonical lease-aware workers: old versions do not honor leases and cannot be fenced retroactively. Queue-only legacy state, ambiguous state, malformed records, or a record that cannot be imported remains a project blockage. Preserve source files, worktrees and evidence; have a support/operator reconcile the evidence and clear the blockage through supported recovery procedures before resuming. Routine manual edits to persistence files are not a promised recovery workflow.

P11 (real Trello Free-tier/API, Git/GitHub, OpenCode and their full task-path compatibility) remains unexecuted and is **not waived** by P2 tests. No live external service was used in this verification. Any production rollout still needs a separately approved, bounded P11 validation against eligible non-paid integrations; do not use paid-only functionality.
